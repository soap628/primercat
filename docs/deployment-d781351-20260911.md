## Production switch and service preservation

The source archive was extracted into a new release directory. The existing
production environment files were copied there with mode `600`, without
printing their contents. Before the switch, the running frontend image was
saved under the rollback tag above.

The new image was built on the server and tested in the no-volume container
`primercat-frontend-check-d781351`, with network mode `none` and a loopback
listener. Checks ran inside that container; no public test port was opened.
The production API rewrite destination was checked in its routes manifest.

The versioned image was then tagged as `primercat-frontend:latest`, followed by:

```sh
cd /root/primercat-d781351
PRIMERCAT_REFERENCE_ROOT=/opt/primercat/reference-data docker compose -p primercat up -d --no-deps --no-build frontend
```

The new frontend passed an internal readiness check for HTTP 200 and the new
homepage markers. The existing nginx configuration passed `nginx -t`, and its
process received `nginx -s reload` at **2026-09-11 09:48:09 UTC**, refreshing the
frontend upstream address without recreating the nginx container.

An exact before/after comparison of container IDs, startup times and complete
mount information passed for `backend`, `db`, `nginx` and `certbot`. Their
containers and mounts were unchanged. The backend's internal `/health` endpoint
returned `{"status":"ok"}`. No reference data, application data, database,
certificate or cache volume was changed by this frontend-only switch.

## Cleanup and rollback

The temporary validation container's release label and zero mounts were
verified before it was stopped and removed. No user data was stored in it.
Both versioned images, the rollback tag and prior release directory were kept.

For a frontend-only rollback, first verify that the saved image has the rollback
ID recorded above. Do not use `rollback-before-49b1d81`, which is an older release.

```sh
cd /root/primercat-d781351
docker image inspect primercat-frontend:rollback-before-d781351 --format '{{.Id}}'
```

After confirming the image identity, save a fresh before/after service snapshot
and restore only the frontend:

```sh
docker tag primercat-frontend:rollback-before-d781351 primercat-frontend:latest
PRIMERCAT_REFERENCE_ROOT=/opt/primercat/reference-data docker compose -p primercat up -d --no-deps --no-build frontend
```

Confirm that the replacement frontend is ready internally. Then validate and
reload the existing nginx process:

```sh
docker exec primercat-nginx-1 nginx -t
docker exec primercat-nginx-1 nginx -s reload
```

Recheck public pages/assets, the running frontend image ID, and the unchanged
identities/startup times/mounts of the other four services. Do not run the
full-stack deployment script, `compose down`, or any volume/image cleanup.
Keep the previous release directory because existing services can retain
configuration bind mounts from it.
